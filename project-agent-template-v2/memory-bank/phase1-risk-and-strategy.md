# Phase1 风险与策略

## 目标

本文件用于记录 Phase1 的关键风险、可能阻塞点、替代方案与验证策略，帮助人类和 AI 在推进任务时做出更稳妥的决策。

## 关键风险

### 风险 1：主流程无法稳定闭环
- 表现：输入到输出链路无法完整跑通
- 影响：Phase1 无法进入后续任务
- 优先策略：先保证最小闭环，再优化质量

### 风险 2：性能或质量不可观测
- 表现：无法统一判断“是否变好/变坏”
- 影响：后续优化缺少判断依据
- 优先策略：尽早建立最小可观测能力

### 风险 3：安全回退不明确
- 表现：核心流程失败时没有稳定兜底
- 影响：主流程不可用，问题难排查
- 优先策略：优先实现 `{{SAFE_FALLBACK_RULE}}`

## 可能阻塞点

- 构建命令不可用
- 测试命令不可用
- 验证样本不足
- 主工程路径不明确
- 外部依赖/环境未准备好

## 替代策略

### 当主方案推进受阻时
- 先用最小可行实现保证闭环
- 用 mock / placeholder 替代尚未成熟的部分
- 把复杂能力拆到 Phase2

### 当验证条件不足时
- 先建立最小验证 checklist
- 先验证关键主路径，不追求一次性覆盖所有边界场景

## 验证建议

Phase1 至少要明确：

- 一条主流程 smoke test
- 一条失败回退验证
- 一条性能/质量指标采集路径
- 一份发布前最小检查清单

## 暂不处理项

- 不影响 Phase1 闭环的体验优化
- 不影响安全回退的增强能力
- 复杂重构与大规模抽象
